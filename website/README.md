# objstore documentation site

The source for <https://kartikrocks.github.io/objstore/>, built with
[Docusaurus](https://docusaurus.io/).

It lives on `main` alongside the code on purpose: a PR that changes documented
behaviour should change the docs in the same review. Docs on a separate branch
drift from the code they describe.

## Local development

```bash
npm ci
npm start        # http://localhost:3000/objstore/
```

## Before pushing

```bash
npm run check    # lint + typecheck + build
```

Individually:

| Command              | Does                                 |
| -------------------- | ------------------------------------ |
| `npm run lint`       | Biome lint + format check            |
| `npm run lint:fix`   | Biome autofix                        |
| `npm run typecheck`  | `tsc` (no-emit set in tsconfig.json) |
| `npm run build`      | production build                     |
| `npm run build:fast` | narrowed build — what CI runs on PRs |

## Editing docs

Pages are Markdown in `docs/`, one file per topic. To add one:

1. Create `docs/<id>.md` with `title` frontmatter.
2. Add the id to `sidebars.ts` under the right category.

The sidebar is explicit rather than autogenerated, so ordering is deliberate
and a new file cannot silently rearrange the nav.

## Versioning

objstore is pre-1.0, so documentation versioning is off — `docs/` serves
directly at `/docs/`. The scaffolding to turn it on at `v1.0.0` (`scripts/cut-version.mjs`,
`versions.config.json`) is already in place. See [VERSIONING.md](VERSIONING.md)
for the full policy and the runbook for switching it on.

## Deployment

Pushing to `main` deploys via `.github/workflows/docs.yml`. There is nothing
to run by hand — do not commit built output to a branch.

## Search

Algolia DocSearch is stubbed out in `docusaurus.config.ts`. Apply at
<https://docsearch.algolia.com/apply/> and uncomment the block once approved.
